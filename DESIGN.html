🎲 ClaudeCube

Rubik's Cube Scrambler & Solver Web Application

Project Overview

ClaudeCube is an interactive web application that simulates a Rubik's cube with the ability to scramble, reset, and solve automatically. The application combines 3D visualization, user interaction, and AI-powered solving algorithms.

🎯 Goal

Create an engaging, interactive Rubik's cube simulator with intelligent solving capabilities.

👥 Users

Puzzle enthusiasts, learners, and developers interested in cube solving algorithms.

📊 Scope

Web-based UI, 3D cube visualization, scrambling logic, and AI solver implementation.

3D Cube Visualization

The cube will be rendered using Three.js for a realistic 3D representation with interactive rotation and movement animations.

Technical Implementation

  • Use Three.js library for WebGL 3D rendering
  • Represent cube state as 6 faces × 9 stickers (3×3)
  • Implement smooth rotation animations for face turns
  • Support mouse/touch controls for interactive rotation
  • Real-time visual feedback for moves

User Interface & Controls

Main Control Buttons

🔀 Scramble Button

Function: Generate random valid moves to scramble the cube.

Behavior:

  • Generate 20-50 random moves
  • Prevent impossible move sequences
  • Animate each move smoothly
  • Update internal state

🔄 Reset Button

Function: Return cube to solved state.

Behavior:

  • Clear move history
  • Animate to solved position
  • Reset solver state
  • Optional confirmation dialog

🤖 Solve Button

Function: Automatically solve the cube.

Behavior:

  • Analyze current state
  • Calculate move sequence
  • Animate each move
  • Display move counter
  • Show solving progress

Secondary Controls

  • Move History Display - Show all moves made
  • Undo/Redo buttons - Navigate through move history
  • Speed Control - Adjust animation speed
  • Auto-Rotate - Spin cube to view different angles
  • Statistics - Display solve time and move count

Core Features

1. Scrambling Engine

Purpose: Create random, solvable puzzle states.

Implementation Details:

  • Valid move set: U, D, L, R, F, B (and variants: U', U2, etc.)
  • Prevent 3-move patterns (X X' X) that revert immediately
  • Generate 20-50 random moves for realistic scrambles
  • Ensure cube remains solvable (no parity issues)

2. Reset Function

Purpose: Restore cube to solved state.

Features:

  • Clear all move history
  • Animate back to home position
  • Reset all UI elements (counters, stats)
  • Optional: Prevent accidental reset with confirmation

3. Solver Algorithm

Purpose: Find and execute solution move sequences.

Algorithm Options:

Algorithm Complexity Move Efficiency Implementation
Layer-by-Layer (Beginner's) Low 50-100 moves Pattern matching + lookup tables
CFOP (Fridrich Method) Medium 50-80 moves 4-phase algorithm
Roux Method Medium 45-60 moves Block building approach
Kociemba Algorithm High 20-30 moves (optimal) Bidirectional BFS + pruning tables

Solver Training Data & Learning

Approach 1: Pattern-Based (No ML Required)

How It Works: Pre-compute solutions for cube patterns and store in lookup tables.

  • Data Sources:
    • Kociemba's solver database (freely available)
    • Pre-computed move tables for edge/corner orientations
    • Manual algorithm libraries (CFOP, Roux algorithms)
  • Advantages: Guaranteed optimal/near-optimal solutions, no training needed
  • Disadvantages: Large memory footprint for full databases

Approach 2: Machine Learning (Advanced)

How It Works: Train neural networks on cube states and solutions.

  • Training Data:
    • Generate synthetic cube states (millions of random scrambles)
    • Compute optimal solutions (using Kociemba or IDA*)
    • Create input-output pairs for training
  • Model Options:
    • Graph Neural Networks (GNN) - for cube state representation
    • Transformer models - for sequence prediction
    • Reinforcement Learning - learn to solve through trial

Recommended Approach: Hybrid

Phase 1 (MVP): Use Kociemba's algorithm or CFOP layer-by-layer

  • Fast implementation
  • No training data needed
  • Proven reliable

Phase 2 (Enhancement): Add ML-based solver

  • Use TensorFlow.js for in-browser inference
  • Train on synthetic data
  • Compare performance with traditional algorithms

Code Architecture Examples

Cube State Representation

const cubeState = { "U": [0, 1, 2, 3, 4, 5, 6, 7, 8], // Up face "D": [0, 1, 2, 3, 4, 5, 6, 7, 8], // Down face "L": [0, 1, 2, 3, 4, 5, 6, 7, 8], // Left face "R": [0, 1, 2, 3, 4, 5, 6, 7, 8], // Right face "F": [0, 1, 2, 3, 4, 5, 6, 7, 8], // Front face "B": [0, 1, 2, 3, 4, 5, 6, 7, 8] // Back face };

Move Function Structure

function executeMove(state, move) { // move: "U", "U'", "U2", "D", etc. const faceMap = { "U": rotateFaceClockwise, "D": rotateFaceClockwise, "L": rotateFaceCounterClockwise }; return faceMap[move.charAt(0)](state); }

Scramble Function

function scrambleCube(state, numMoves = 25) { const moves = ["U", "D", "L", "R", "F", "B"]; const variants = ["", "'", "2"]; let current = state; for (let i = 0; i < numMoves; i++) { const move = moves[Math.floor(Math.random() * 6)] + variants[Math.floor(Math.random() * 3)]; current = executeMove(current, move); } return current; }

Key Design Decisions

3D vs 2D Visualization

Decision: Use 3D rendering with Three.js

Rationale: Better user experience, more intuitive interaction, professional appearance

Algorithm Choice

Decision: Start with layer-by-layer, expand to CFOP

Rationale: Balance between simplicity and efficiency

State Management

Decision: Client-side only, no backend

Rationale: Faster, simpler, all computation on user's device

Browser Compatibility

Decision: Modern browsers (ES6+)

Rationale: Leverage latest web standards, simpler code
